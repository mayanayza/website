written_content: "Luna is a tool for artists and creative technologists which automates\
  \ the creation, management, and syndication of art and personal projects across\
  \ various channels. As I started to create more art, the toil of managing and organizing\
  \ my work across different platforms became annoying, so I decided to create a tool\
  \ to streamline it all.\n\nLuna does the following through a simple CLI:\n- Creates\
  \ local project directories to store work-in-progress files and media, \n- Sets\
  \ up a GitHub repository for your project\n- Optionally, creates a Things 3 project\n\
  ...all with consistent organization and metadata.\n\nOnce ready, Luna also facilitates\
  \ syndication of project content through various channels:\n- A portfolio website\
  \ (designed for websites powered by Jekyll)\n- Github\n- PDF summaries for submission\
  \ to open call and exhibitions\n\nAlmost all of the content on my website is managed\
  \ using Luna."
readme: "## Features\nProvides a single source-of-truth for all project information\
  \ to eliminate toil in managing across various channels\n- Creates standardized\
  \ project structure on local machine to more easily manage project content and media\
  \ files\n- Initializes git repository\n- Generates and publishes content for various\
  \ channels based on project info\n\t- Website post content and a roadmap of active\
  \ work (designed for Jekyll websites)\n\t- PDFs for submitting to open calls with\
  \ a variety of formatting options\n\t- Github for technical content and documentation\
  \ / readme information\n\t- Raw files to local output folder for other uses\n- Optionally\
  \ integrates with Things 3 on MacOS\n\n## Setup\n1. Clone the repository:\n```bash\n\
  git clone git@github.com:yourusername/project-automation.git\ncd src\n```\n\n2.\
  \ Create and activate a virtual environment:\n```bash\npython -m venv .venv\nsource\
  \ .venv/bin/activate  # On Windows: venv\\Scripts\\activate\n```\n\n3. Install dependencies:\n\
  ```bash\npip3 install -r requirements.txt\n```\n\n4. Create your environment file:\n\
  ```bash\ncp .env.example .env\n# Edit .env with your values\n```\n\n5. Run script\
  \ commands from root directory\n```bash\ncd ..\n```\n\n## Environment Variables\n\
  - `WEBSITE_DOMAIN`: The domain on which your Jekyll website will ultimately be served\n\
  - `PROJECT_BASE_DIR`: Path for where you would like to create and manage projects\n\
  - `WEBSITE_DIR`: Path to where your website content is located\n- `WEBSITE_POSTS`:\
  \ Relative path to WEBSITE_DIR where your website posts are located\n- `WEBSITE_MEDIA`:\
  \ Relative path to WEBSITE_DIR where your website media is located\n- `WEBSITE_PAGES`:\
  \ Relative path to WEBSITE_DIR where your website pages are located\n- `ENABLE_ROADMAP`:\
  \ Enable/disable generating a roadmap page based on your projects for your website\n\
  - `GITHUB_USERNAME`: Your GitHub username\n- `GITHUB_TOKEN`: Your GitHub personal\
  \ access token\n- `ENABLE_THINGS3`: Enable/disable Things 3 integration (true/false)\n\
  - `THINGS3_AREA`: Area where projects should be created\n\n## Usage\n\n### Create\
  \ a new project:\n```bash\npython -m src.script.main --command create\npython -m\
  \ src.script.main --c create\n```\n\n### List all projects:\n```bash\npython -m\
  \ src.script.main --command list\npython -m src.script.main --c list\n```\nThis\
  \ will show all projects with their names, creation dates, and status.\n\n### Rename\
  \ project:\n```bash\npython -m src.script.main --command rename\npython -m src.script.main\
  \ --c rename\n```\n\n### Delete project:\n```bash\npython -m src.script.main --command\
  \ delete\npython -m src.script.main --c delete\n```\n\n### Publish project updates:\n\
  ```bash\n# Publish all projects to all channels\npython -m src.script.main --command\
  \ publish --all-projects --all-channels\n\n# Publish specific projects to all channels\n\
  python -m src.script.main --command publish --projects project1 project2 --all-channels\n\
  python -m src.script.main --command publish --p project1 project2 --all-channels\n\
  \n# Publish specific projects to specific channels\npython -m src.script.main --command\
  \ publish --p project1 project2 --channels channel1 channel2\npython -m src.script.main\
  \ --command publish --p project1 project2 --ch channel1 channel2\n```\n\n### Channel-specific\
  \ publishing options and information\n\n#### PDF\n\nUses files in media/ directory,\
  \ metadata.yml, content.md, README.md\nOutputs PDF to \\_output folder in base directory\n\
  \n```bash\n# Publish (generate PDF with images collated into same document).\npython\
  \ -m src.script.main --c publish --p project1 --ch pdf --collate-images\npython\
  \ -m src.script.main --c publish --p project1 --ch pdf -ci\n\n# Publish (generate\
  \ PDF with separate image files)\n\n## Prepend optional text to image files\npython\
  \ -m src.script.main --c publish --p project1 --ch pdf --filename-prepend\npython\
  \ -m src.script.main --c publish --p project1 --ch pdf -fp\n\n## Set max image dimensions\n\
  python -m src.script.main --c publish --p project1 --ch pdf --max-width 1200 --max-height\
  \ 800\npython -m src.script.main --c publish --p project1 --ch pdf -mw 1200 -mh\
  \ 800\n```\n\n#### Github\n\nUses files in media/ directory, metadata.yml, content.md\n\
  \n```bash\n# Stage (generate README.md)\npython -m src.script.main --c stage --p\
  \ project1 --ch github\n\n# Publish (commit and pushing to Github). Commit message\
  \ required.\npython -m src.script.main --c publish --p project1 --ch github --commit-message\
  \ 'message'\npython -m src.script.main --c publish --p project1 --ch github -cm\
  \ 'message'\n```\n\n### Web\n\nUses files in media/ directory, metadata.yml, content.md\n\
  Project status must be set to `complete` for this publication option to work\n\n\
  ```bash\n# Stage (generate posts, roadmap, links page)\npython -m src.script.main\
  \ --c stage --p project1 --ch github\n\n# Publish (commit and push change to Github).\
  \ Commit message auto-generated.\npython -m src.script.main --c publish --p project1\
  \ --ch web\n```\n\n### Raw\n\nUses files in media/ directory, metadata.yml, content.md,\
  \ README.md\nOutputs to \\_output/project_name folder in base directory\n\n```bash\n\
  # Publish (flattens content and media files and puts into one folder)\npython -m\
  \ src.script.main --c publish --p project1 --ch raw\n```\n\n## Project Structure\n\
  Each project is created with the following structure:\n```\nproject-name/\n├── src/\n\
  ├── media/\n│   ├── images/\n│   ├── videos/\n│   ├── audio/\n│   ├── docs/\n│ \
  \  └── models/\n├── media-internal/\n│   ├── images/\n│   ├── videos/\n│   ├── audio/\n\
  │   ├── docs/\n│   └── models/\n├── content/ \n│   ├── content.md\n│   ├── metadata.yml\n\
  │   └── README.md\n```\n\nmedia-internal is for organizing WIP assets which wil\
  \ not be committed to Github. Final media files which are ready to be syndicated\
  \ in different channels, media files should be moved to the corresponding media/\
  \ subfolder.\n\n## Development\nTo add a channel\n1. Create a new .py file for the\
  \ channel in the channels/ directory\n2. Create any necessary template files for\
  \ the channel in the templates/ directory\n3. Add automation to automation.py\n\
  4. Add channel to channel registry in main.py\n\n## Things 3 Integration\nThe script\
  \ provides a simple integration with Things 3 on macOS, and will create a project\
  \ in the area specified in the .env file upon project creation.\n\n\n\n"
